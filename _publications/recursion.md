## Ռեկուրսիա

Elixir-ում ցիկլեր չկան։ Կրկնվող գործողությունները կատարվում են ռեկուրսիայով կամ բարձր մակարդակի ֆունկցիաներով, ինչպիսիք են մեզ ծանոթ `Enum` module-ի ֆունկցիաները։ Այս հոդվածում կդիտարկենք ռեկուրսիան։

Նշենք նաև, որ Elixir-ի `for`-ը ցիկլ չէ։ Այն մակրո է։

### Ցիկլերը ռեկուրսիայի միջոցով

Ենթադրենք պետք է կրկնապատկել զանգվածի բոլոր արժեքները JavaScript-ում.

```javascript
for (let i = 0; i < prices.length; i++) {
  prices[i] = prices[i] * 2;
}
```

Այս կոդը փոխում է `prices` զանգվածը։ Նոր արժեքները գրվում են նույն տեղում։ Java-ում և C#-ում մոտեցումը նույնն է։

Elixir-ում տվյալներն անփոփոխ են։ Ցուցակի պարունակությունը փոխել հնարավոր չէ։ Ուստի `prices[i] = ...` ձևով գրելու միջոց չկա։

Փոխարենն ունենք ռեկուրսիա, երբ ֆունկցիան կանչում է ինքն իրեն։ Կանչերը շարունակվում են, քանի դեռ չենք հասել պայմանին, որը կանգնեցնում է կրկնությունը։ Ոչ մի տվյալ չի փոփոխվում. ամեն քայլում ստեղծվում է նոր արժեք։

Դիտարկենք գործնական խնդիր։ Հաճախորդը վերցրել է ապառիկ և ամեն ամիս վճարում է ֆիքսված գումար։ Անհրաժեշտ է ցույց տալ, թե որքան պարտք է մնում ամեն վճարումից հետո։

`Loan` module-ը պարունակում է մեկ ֆունկցիա՝ `schedule/2`։ Այն ստանում է ընդհանուր պարտքը և ամսական վճարի գումարը։ Վերադարձնում է մնացորդների ցուցակը.

```elixir
defmodule Loan do
  def schedule(balance, payment) when balance > 0 do
    [balance - payment | schedule(balance - payment, payment)]
  end

  def schedule(0, _payment) do
    []
  end
end
```

```elixir
iex> Loan.schedule(10000, 2500)
[7500, 5000, 2500, 0]
```

Ցուցակի յուրաքանչյուր թիվ ցույց է տալիս մնացած պարտքը հերթական վճարումից հետո։ Չորրորդ վճարումից հետո պարտքը մարվում է։

Ինչպես `case`-ում, ֆունկցիան կարող է ունենալ մի քանի ճյուղ։ Կատարվում է առաջին ճյուղը, որին համապատասխանում են արգումենտները։ Guard-ը նույնպես պետք է կատարվի։

Առաջին կանչում `balance`-ը `10000` է։ Այն բավարարում է guard-ի `balance > 0` պայմանին։ Ֆունկցիան հաշվում է նոր մնացորդը՝ `7500`, ավելացնում է այն ցուցակի սկզբում և կանչում ինքն իրեն։

Նույնը կրկնվում է `7500`, `5000` և `2500` արժեքների համար։

Երբ `balance`-ը դառնում է `0`, այն այլևս չի բավարարում guard-ի պայմանին։ Հետևաբար առաջին ճյուղը բաց է թողնվում, և կատարվում է երկրորդը՝ ավարտի ճյուղը։ Այն վերադարձնում է դատարկ ցուցակ։ Վճարի գումարն այստեղ պետք չէ, ուստի կոմպիլյատորի զգուշացումից խուսափելու համար պարամետրի անվան սկզբում ավելացնում ենք ընդգծման նշանը՝ `_payment`։

Ավարտի ճյուղն ամենակարևոր մասն է։ Առանց դրա ֆունկցիան անվերջ կկանչեր ինքն իրեն։

Ավարտի ճյուղը պետք է միշտ հասանելի լինի։ Դիտարկենք դեպք, երբ պարտքը ամսական վճարի վրա առանց մնացորդի չի բաժանվում.

```elixir
iex> Loan.schedule(10000, 3000)
** (FunctionClauseError) no function clause matching in Loan.schedule/2
```

Մնացորդները լինում են `7000`, `4000`, `1000`, ապա `-2000`։ `-2000`-ը չի բավարարում `balance > 0` guard-ին, բայց և չի համընկնում schedule(0, _payment)-ի կանչի համար։ Ինչպես տեսնում ենք, ոչ մի ճյուղ չի համապատասխանում, որը և սխալ է առաջացնում։

### reduce և map ալգորիթմները

Ենթադրենք՝ գնումների զամբյուղում կան ապրանքներ, և մեզ անհրաժեշտ է հաշվել ընդհանուր գումարը։

`Cart.total/2`-ը ստանում է երկու արգումենտ՝ ապրանքների գների ցուցակը և կուտակիչը (accumulator)։ Կուտակիչում պահվում է ընթացիկ գումարը.

```elixir
defmodule Cart do
  def total([head | tail], accumulator) do
    total(tail, head + accumulator)
  end

  def total([], accumulator) do
    accumulator
  end
end
```

```elixir
iex> Cart.total([1200, 3500, 800], 0)
5500
```

Առաջին կանչում `[1200, 3500, 800]` ցուցակը համընկնում է `[head | tail]`-ի հետ։ `head`-ը դառնում է `1200`, `tail`-ը՝ `[3500, 800]`։ `accumulator`-ը `0` է։

Ֆունկցիան գումարում է `head`-ը կուտակիչին։ Այնուհետև կանչում է ինքն իրեն և փոխանցում `tail`-ը։ Քայլերը հետևյալն են.

```elixir
total([1200, 3500, 800], 0)
total([3500, 800], 1200)
total([800], 4700)
total([], 5500)
```

Ցուցակը դատարկվում է, իսկ դատարկ ցուցակի դեպքում բնականաբար կանչվում է ավարտի ճյուղը։ 

Երբ ցուցակից ստանում ենք մեկ արժեք, այդ գործընթացը կոչվում է reduce ալգորիթմ։ Այն ֆունկցիոնալ ծրագրավորման հիմնական մոտեցումներից է, և մենք ծանոթ ենք դրան Enum մոդուլի reduce ֆունկցիայի օրինակով։

Այժմ դիտարկենք այլ խնդիր։ Յուրաքանչյուր ապրանքի գնին ավելանում է փաթեթավորման վճար։ Անհրաժեշտ է ստանալ նոր գների ցուցակը՝ նույն երկարությամբ։

`Pricing.with_fee/2`-ը ստանում է գների ցուցակը և վճարի գումարը.

```elixir
defmodule Pricing do
  def with_fee([head | tail], fee) do
    [head + fee | with_fee(tail, fee)]
  end

  def with_fee([], _fee) do
    []
  end
end
```

```elixir
iex> Pricing.with_fee([1200, 3500, 800], 100)
[1300, 3600, 900]
```

Ռեկուրսիան անցնում է ցուցակի վրայով, և յուրաքանչյուր տարրի համար վերադարձնում նոր, փոխված արժեք։ Այս գործընթացը կոչվում է map ալգորիթմ, և մենք ծանոթացել ենք դրան կրկին Enum մոդուլին նվիրված դասերից մեկում։

Ռեկուրսիան Elixir-ի կարևոր մասն է։ Սակայն գործնականում ցուցակների հետ այս ձևով հազվադեպ են աշխատում։

Ինչպես արդեն նշեցինք, `Enum` module-ը, որը դիտարկել ենք նախորդ հոդվածներում, ներկայացնում է պատրաստի ֆունկցիաներ, որտեղ այս ալգորիթմերն արդեն իրականացված են, և գործնական առաջադրանքների ժամանակ մենք բնականաբար օգտագործելու ենք լեզվի ստանդարտ գրադարանների կողմից տրամադրվող լուծումները.

```elixir
iex> Enum.reduce([1200, 3500, 800], 0, fn price, acc -> price + acc end)
5500
iex> Enum.map([1200, 3500, 800], fn price -> price + 100 end)
[1300, 3600, 900]
```

Կամ `&` (capture-ի) միջոցով.

```elixir
iex> Enum.reduce([1200, 3500, 800], 0, &+/2)
5500
iex> Enum.map([1200, 3500, 800], &(&1 + 100))
[1300, 3600, 900]
```

Այժմ պարզ է, թե ինչի վրա են կառուցված `Enum`-ի ֆունկցիաները։ Դրանք հենց այս ռեկուրսիվ ալգորիթմներն են։
